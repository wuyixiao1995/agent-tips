# 长任务接力（会话连续性）

> 一个 session 聊太长，agent 会「变蠢」；换个 session 开工，又「失忆」不记得上次干到哪。这个技巧用一套「收尾 / 继续」协议，把长任务切成一段段干净的对话——进度不丢、状态可接力、不用从头讲。

## 一、要解决什么问题

长任务跑在一个 session 里，越拖越蠢——上下文窗口里堆的信息越多，agent 的有效注意力越被稀释，表现为忘记早期决策、重复已否定的方案。这叫 **context rot（上下文腐烂）**。

但如果把任务切成多个 session，又面临另一个问题：新 session 不知道上次干到哪了——持久记忆如果没写全或被截断，状态就断了。这叫 **amnesia（失忆）**。

两难的本质：**一个 session 装太多会烂，拆开了又容易丢。**

## 二、核心解法：收尾 / 继续循环

与其让一个 session 越来越长，不如把进度压缩成一份**自包含的「交接件」**，让下一个 session 只读这一份就能接续。

### 收尾协议（6 步，顺序不可反）

当一个 session 要结束时，执行收尾：

| 步骤 | 做什么 | 目的 |
|---|---|---|
| 1. 追加日志 | 在当天日志文件 append 一行摘要 | 留痕，供未来回溯 |
| 2. 写交接件【本session】段 | 本次做了什么、卡点、未决项 | 每次**必须**更新 |
| 3. 更新【主线状态】段 | 如果是主线任务，同步当前节点+下一步 | 让「继续」有准星 |
| 4. 按需更新记忆 | 只沉淀跨任务可复用的条目 | 不搬过程数据，防记忆膨胀 |
| 5. 输出 5 段式简报 | 目标/决定/规则(引原话)/状态/下一步 | 给用户一个可读的收尾报告 |
| 6. 告知收尾完成 | session 可结束 | 明确的终点信号 |

### 继续协议（4 步）

新 session 开始时，执行继续：

1. **识别模式**：裸「继续」=回主线；「继续 [任务名]」=接特定任务
2. **取权威源**：从交接件【主线状态】或日志中找该任务最近记录。如果系统已在开场注入了记忆，不重复读（冗余读取=浪费上下文）
3. **上下文纪律**：以【主线状态】为准星找下一步，不拉跨空间的记忆与无关任务（防越界）
4. **输出就绪摘要**：先给「已做/卡点+待厘清问题」，不高频抛选择题

### 交接件 = 两段式结构

交接件（比如叫 `HANDOFF.md`）只有两个段：

- **【主线状态】**：主线的当前节点 + 下一步。只在主线收尾时更新。
- **【本session】**：本次 session 做了什么、卡点、未决。每次收尾都更新。

交接件只放**浓缩后的上下文 + 指路（路径/URL）**，不抄 specs、不抄计划树、不抄日志原文；API key、密码一律脱敏。这样它保持精简，新 session 读一份就够。

## 三、分层架构：逻辑层 vs 介质层

这是本技巧最关键的设计决策——**逻辑和介质分离**：

- **逻辑层**：收尾 6 步、继续 4 步、交接件结构、5 段式简报——架构通用，任何带「持久注入记忆 + 长 session」结构的 agent 都适用，不绑定任何平台。
- **介质层**：具体平台的文件路径、截断阈值、检查脚本——这些会过期。换平台时只改这一层，逻辑层不动。

为什么这么分：**逻辑不会过期，介质会。** 如果把路径写死在逻辑里，换平台就得重写整个协议；分开后，换介质只是「改几行路径」的事。

## 四、一个重要前置：注入层治理

本技巧和「注入层治理」（保证持久记忆文件不被平台静默截断）构成垂直栈：

- **地基**：注入层治理——保住持久记忆层不溢出、不被截断
- **上层建筑**：本技巧——靠读记忆 + 交接件把状态接力到下一 session

关键：**地基烂了，继续接起来也是接进一个失忆的 agent**——因为继续读的记忆文件本身已被截秃。

## 五、怎么用

直接把本目录的 [`SKILL.md`](./SKILL.md) 装进你的 agent（WorkBuddy / Claude Code / OpenClaw 等任何支持 skill 的平台），然后：

- **「收尾」**：当前 session 快满了或任务告一段落，说一声，agent 跑收尾协议
- **「继续」**：新 session 开工，说一声，agent 读交接件+记忆，输出就绪摘要，你不用重新交代背景

触发词可自定义（如「交班」「接着干」）——让 agent 改 SKILL.md 顶部变量即可。若你的平台没有自动注入记忆机制，需自行保证记忆/交接件在 session 开头被读取（见 SKILL.md §2 的说明）。
